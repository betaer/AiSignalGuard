# AI Signal Guard

AI Signal Guard 是一个纯静态的数字身份匹配分析工具。它比较出口 IP、网络类型、DNS、WebRTC、语言、时区、浏览器与服务访问路径等环境信号，回答两个更直接的问题：互联网看到的数字环境是什么样，以及它与目标用户画像有多接近。

项目只分析网络与浏览器环境，不判断访问者的真实国籍、职业或个人身份。所有检测结果仍在当前浏览器中组织和评分。

## 它解决什么问题

普通 IP 查询只能告诉你一个地址、地区或 ASN，但网页实际能同时观察 DNS 解析器、WebRTC 候选地址、系统时区、浏览器语言、字体、指纹特征和目标站点访问路径。单独看每个参数，很难判断这些信号共同构成了怎样的数字画像。

AI Signal Guard 会先给你 6 秒选择目标身份；如果没有选择，则自动使用通用数字身份画像运行检测。具体画像会用专属权重生成一个 Identity Match Score；通用分析不预设目标画像，因此只给出数字环境综合结论，不展示百分制匹配分。结果先呈现“为什么像 / 为什么不像”和调整建议，再把每项身份信号放回对应的真实检测模块。

页面不会把启发式结果包装成平台风控结论。完整 IP、DNS、WebRTC、AI 路径和浏览器证据仍保留在结果页下方，便于逐项核对。每个检测模块顶部的卡片是该模块的结论摘要：与目标画像直接相关的项目显示“目标身份匹配”，身份信号、AI 路径和 AI 平台状态中只用于排障的项目显示“参考”，并明确标注“不计入身份匹配分”。

## 核心能力

| 模块 | 检查内容 | 用途 |
|---|---|---|
| 目标身份选择 | AI 用户、自媒体创作者、跨境商家及通用分析 | 明确本次分析希望比较的数字画像；美国普通用户配置暂不在选择页展示 |
| Identity Match Score | 画像动态权重、证据置信度、覆盖率与关键差异约束 | 判断当前环境与所选具体画像的相似程度；通用分析不展示百分制分数 |
| 身份解释 | 一句话总结、为什么像、为什么不像、尚未确认、改进建议 | 把专业信号转换成可理解且可追溯的结论 |
| 高级网络风险诊断 | 原有启发式风险信号与分项证据 | 默认折叠，显示风险状态与风险项数量，不再与身份匹配分并列显示第二个百分制分数 |
| 出口 IP | IPv4-only / IPv6-only 路径、地区、ASN、组织、网络类型及多源证据 | 判断双栈和分流场景下的核心网络出口质量 |
| 身份一致性 | 浏览器语言、系统时区、Emoji、中文字体 | 检查环境画像是否前后矛盾 |
| WebRTC 泄漏 | STUN 候选地址、公网/内网/mDNS 分类 | 发现代理外真实公网地址暴露 |
| DNS 泄漏 | 标准/深度 DNS 泄漏检测、中国解析器识别 | 判断 DNS 是否跟随代理或隧道 |
| 网络连通 | AI 服务、内容平台、商业服务、开发者生态、全球与中国站点的浏览器可达性 | 只显示“可达 / 本次未连通”二态：收到目标端点或其备用端点任何 HTTP 响应时显示“可达”；主、备用探针均未取得可用响应信号时显示“本次未连通”。结果只代表浏览器请求路径，不代表登录、解锁、账号、支付功能或平台健康状态 |
| 多源交叉 | 多个 IP 情报源互证 | 发现 IP 地理、ASN、组织信息冲突 |
| AI 路径 | ChatGPT、Claude、OpenAI、Perplexity 等目标看到的来源 IP、服务侧国家标签和接入节点 | 区分目标站视角与用户物理位置；模块顶部显示“服务出口参考”，Cloudflare 基准与该参考摘要不计入身份匹配分 |
| AI 状态 | OpenAI / Claude 官方状态接口 | 排除平台自身故障；模块顶部显示“平台运行参考”，不参与身份匹配分 |
| 浏览器指纹 | User-Agent、浏览器平台标识、CSS 屏幕、逻辑线程数估计、设备内存估计、Canvas、Audio 等 | 查看网页脚本能读到的浏览器环境，并标明兼容性字符串与隐私保护估计值的边界 |
| 路由追踪 | macOS / Windows / Linux 命令模板 | 用本机命令复核浏览器无法执行的路径追踪 |
| 复制给AI诊断 | 结构化 Markdown 网络诊断报告 | 始终脱敏；IPv4 仅保留前三段、IPv6 仅保留前三组，mDNS、Canvas 与声纹标识不写入原值 |
| 分享 | 280 加权字符内的身份结论摘要 | 只复制画像、匹配分、覆盖率和主要正反原因，不带 IP / DNS / 指纹值 |
| 浮动工具栏 | 重新测试、复制给AI诊断、分享、隐藏 / 取消隐藏、GitHub Star、回到顶部 | 保留五项站内主操作，并恢复仓库 Star 数入口；数量从 GitHub 公开仓库信息读取并短时缓存，接口失败时保留可点击的 `Star` 回退文案；ChatGPT、Claude 独立快捷入口不再占用工具栏 |

## 隐私边界

AI Signal Guard 是纯静态页面，没有自建后端。部分检测必须请求第三方公开接口，页面会尽量把“本机计算”和“外部请求”边界讲清楚。

| 类型 | 是否离开浏览器 | 说明 |
|---|---:|---|
| 语言、时区、字体、Emoji、指纹 | 否 | 在本机浏览器内读取和计算 |
| 出口 IP、多源 IP 情报 | 是 | 会请求第三方 IP 情报接口 |
| WebRTC | 是 | 会访问 STUN 服务以观察候选地址 |
| DNS 泄漏 | 是 | 通过第三方 DNS 泄漏检测服务完成 |
| 服务可达性、AI 路径、AI 状态 | 是 | 会请求对应公开探针或状态接口；跨站结果只作为可达性或路径信号，官方服务状态只用于排障 |
| 分享 | 否 | 只包含画像、匹配分、覆盖率和主要正反原因，不复制 IP、DNS、组织和指纹值 |
| 复制给AI诊断 | 否 | 只写入本机剪贴板，报告无条件对出口、DNS、WebRTC 与 AI 路径地址脱敏，不会自动打开或发送给第三方 |
| Google Analytics | 是 | 网站延迟加载 GA 统计访问情况，会向 Google 发送页面地址、页面来源（referrer）、客户端标识、语言、屏幕分辨率、浏览器与系统版本等元数据；检测结果本身不会上传 |

## 快速使用

1. 打开 [https://betaer.github.io/AiSignalGuard/](https://betaer.github.io/AiSignalGuard/)。
2. 在 6 秒倒计时内选择目标数字身份；也可以点击绿色倒计时主按钮、手动跳过，或等待页面自动使用通用分析。
3. 进入分析后等待环境信号检测完成。
4. 具体画像先看唯一的 Identity Match Score；通用分析直接看数字环境综合结论。随后查看正反原因和调整建议。
5. 身份信号已经嵌入出口 IP、身份信号、网络泄漏、服务连通和多源交叉等对应模块，点击“目标身份匹配”条目可查看权重、贡献与证据。
6. 点击“复制给AI诊断”获得默认脱敏的结构化报告，再自行粘贴到任意 AI；“分享”保留 280 加权字符内摘要。
7. 右下角“隐藏 / 取消隐藏”只控制页面敏感字段的显示；高级网络风险诊断默认折叠且不展示第二个百分制分数。
8. 如需复核路由路径，可复制页面给出的 macOS / Windows / Linux 命令在本机终端执行。

页面首次打开后的 6 秒选择期内不会自行运行检测。选择画像会取消自动进入；如果始终没有选择，可以点击绿色倒计时主按钮立即开始，也可以等待倒计时结束后使用通用画像访问 IP 情报、DNS、WebRTC 和服务探针。

## 本地开发与访问

Git 分支共享同一个工作目录，不会为每个分支生成一套重复文件。切换到开发分支后，源文件仍位于项目根目录：

```bash
git switch codex/digital-identity-analysis
npm install
npm run dev
```

然后访问终端输出的 `http://127.0.0.1:端口/`。虽然生产压缩包继续兼容直接打开 `index.html`，本地开发仍推荐使用 HTTP 服务，避免浏览器对跨域请求、模块和本地文件的额外限制。

发布前先运行完整确定性回归，再单独验证 Claude 与 Perplexity 的真实跨域探针契约：

```bash
npm run check:full
npm run test:connectivity-live
```

第二条命令会从真实 Chromium 请求两个服务各自域名下的诊断端点，只核对 HTTP 状态与 CORS 响应类型，不读取或输出诊断正文。

## 部署

项目根目录直接提供最新正式版 `index.html`，GitHub Pages 使用 `main` 分支根目录发布即可。历史版本使用目录归档：

```text
index.html       # 最新正式版，当前对应 v2
v1/index.html    # v1 固定入口
v2/index.html    # v2 固定入口
```

不再额外维护 `index-v1.0.html`、`index-v2.0.html` 之类的平铺副本。发布提交使用 annotated tag 标记，并建立同名 GitHub Release；GitHub 会自动提供源码 ZIP / TAR。静态站点不使用 GitHub Packages，也不维护长期 `v1` / `v2` 分支，避免多个版本分支之间的修复漂移。

## 能力边界

- 不导出截图或 JSON 归档，避免把敏感诊断数据变成易传播文件。
- Netflix、TikTok、Instagram、PayPal、Stripe 等服务在纯浏览器且不使用官方接口时，只能观察可达性或访问路径，不能据此判断内容区域、账户状态或交易能力。
- 服务探针统一使用“可达 / 本次未连通”两种终态。跨域端点即使不向浏览器公开 HTTP 状态，只要收到响应仍显示“可达”；可读取的非 2xx 同样证明请求路径已建立，但不代表业务功能正常。主探针与备用探针均因扩展拦截、超时、DNS / TLS 失败、浏览器跨域策略或网络策略等原因未取得可用响应信号时，显示“本次未连通”，不等同于平台宕机。Claude 与 Perplexity 使用各自官方域名上可跨域读取的 `/cdn-cgi/trace` 诊断端点，避免 favicon 的 CORP 策略造成假性未连通；npm Registry 优先读取其用于健康检查的 `tiny-tarball` 包元数据，并以 `/-/ping` 作为只读备用端点。
- 状态徽标同时使用文字与符号：`✅ 匹配`、`❗ 部分匹配`、`‼️ 存在差异 / 高风险`、`⁉️ 未确认`；身份信号中的符号使用随状态变化的圆形色调底座，不只依赖颜色传达结论。
- 高级网络风险汇总只为非零计数提供页内链接：数字带统一下划线，点击或按 Enter 会定位并展开第一条对应证据，同时更新页面锚点；`0 项`保持普通文本。高风险与需留意的多项信号仍可通过下方风险气泡逐项定位，未确认计数会定位到首个未确认分区。
- 浏览器指纹中的 `navigator.platform`、`navigator.hardwareConcurrency` 和 `navigator.deviceMemory` 分别是浏览器兼容性标识、逻辑处理器数量和隐私保护后的内存估计；它们不能替代 macOS“系统信息”中的真实硬件规格。
- 移动网络、住宅宽带、云厂商、代理池等归类依赖第三方 IP 情报和 ASN / 组织字段，只作为启发式证据，不作为绝对结论。
- 出口地址先返回时会立即展示，但评分节点保持“检测中”；所有 IPv4 / IPv6 地址源及必要的显式地址情报完成后才给出最终状态。同一 IP 的不同来源按证据合并，无法形成多数共识时显示为未确认，不会用单个冲突来源直接判红或判绿。
- AI 路径里的国家是目标站 / Cloudflare 返回的服务侧标签，不等于用户、运营商或服务器的物理位置。Cloudflare 基准不参与评分；实际 AI 目标需至少两个目标、且每个目标两次采样一致命中当前口径时，才触发对应扣分。
- iCloud Private Relay、Cloudflare WARP、运营商代理和按域名分流可能让不同目标看到不同出口。此时页面会保留各条路径，而不是强行把它们合并成一个“真实位置”。
- 当数据源没有返回明确的网络类型、隐私标记或运营商信息时，页面不会凭空推断，只展示可验证的字段和疑似风险。
