# AI Signal Guard

[简体中文](README.md) · [English](docs/readme-en.md)

## 浏览器端 AI 网络与环境信号检测

核对出口 IP、DNS、WebRTC、时区、语言、浏览器环境与 AI 服务路径，快速发现泄漏、冲突和异常信号。

适用于 Claude、ChatGPT、Gemini 等 AI 服务的网络排障、环境一致性核对与访问前预检。

[在线检测](https://betaer.github.io/AiSignalGuard/) · [提交问题](https://github.com/betaer/AiSignalGuard/issues/new/choose) · [查看源码](https://github.com/betaer/AiSignalGuard) · [![Visitors](https://visitor-badge.laobi.icu/badge?page_id=betaer.AiSignalGuard)](https://github.com/betaer/AiSignalGuard)

[![AI Signal Guard 社交预览](https://raw.githubusercontent.com/betaer/AiSignalGuard/main/tuiguang/social-preview.png)](https://github.com/betaer/AiSignalGuard/blob/main/tuiguang/social-preview.png)

AI Signal Guard 不判断访问者的真实国籍、职业或个人身份，也不承诺账号解锁或规避平台风控。它回答的是：**当前浏览器向不同网络端点暴露了哪些网络与环境信号，这些信号是否一致，以及证据是否足够。**

> 网络参考分基于本轮可观察信号生成，不代表平台账号状态、封号概率或平台内部风控结论。

## 核心优势

- **多源而非单源**：IP 情报、路由注册、WebRTC 与 STUN 分别保留来源级状态和证据。
- **失败不冒充安全**：超时、字段缺失和请求失败保持“失败 / 未知”，不参与安全票。
- **结论可追溯**：摘要、评分、正反原因均可回到对应来源和原始检测模块。
- **边界明确**：区分浏览器本地计算、第三方网络请求、启发式推断和无法验证的业务状态。

## 核心能力

| 模块 | 检查内容 | 输出用途 |
|---|---|---|
| 出口 IP | IPv4 / IPv6、国家与地区、ASN、组织、网络类型、多源冲突 | 理解不同地址族和不同目标看到的出口 |
| DNS 泄漏 | 随机子域探测、解析器地址与地区 | 核对解析器与出口地区，失败保持未知 |
| WebRTC | 两组节点收集服务器反射候选与公网 host 候选，按 IPv4 / IPv6 分开比对 | 发现候选与同族 HTTP 出口差异；公网 host 不冒充 STUN 响应 |
| 路由与注册 | IANA、RIR、RIS、WHOIS、Cymru、PeeringDB 等来源 | 校验目标 IP、前缀、RDAP 范围和查询 ASN，再核对路由起源 |
| 环境一致性 | 浏览器语言、IANA 时区归属、Canvas 与字体 API 能力、设备公开信息 | 核对地区与环境信号；未知或多国共用时区不强行归国 |
| 浏览器指纹 | Canvas、本地摘要、屏幕、平台、逻辑线程、内存估计、WebAudio | 查看网页脚本在当前浏览器能读取或计算的暴露面 |
| AI 服务路径 | ChatGPT、Claude 的公开路径回显与备用资源；Gemini 的公开资源 | 区分路径已读取、资源可达、不透明响应、HTTP 受限、超时与失败 |
| 报告与分享 | 随隐私开关脱敏的文本报告、短摘要 | 便于人工复核或自行粘贴给 AI 分析，不会自动外发 |

## 多源证据架构

### 确定性的来源注册表

当前 v2 在启动时校验以下来源池数量和唯一性：

| 证据池 | 数量 | 调度方式 |
|---|---:|---|
| IP 情报来源 | 10 家 / 每个可用地址族 | IPv4、IPv6 分开查询与汇总 |
| 路由与注册来源 | 10 路 / 每个可用地址族 | 已取得出口后启动，依赖 ASN 的项需形成共识 |
| WebRTC 主检测池 | 10 个独立节点 | 每个节点使用独立 `RTCPeerConnection` |
| 补充 STUN 池 | 10 个独立节点 | 不复用主池候选，独立保留终态 |

两组 WebRTC / STUN 池合计 20 次节点尝试，但文档和界面按“主池 10 + 补充池 10”分别展示，避免把不同角色的证据混成一个夸大的节点数字。

公网 host 是浏览器可见的本地接口地址，可能包含原生 IPv6；它参与同族 HTTP 核对，但重复出现在多个连接中不代表多个 STUN 节点均已响应。局域网、链路本地、mDNS 与中继候选不作为公网出口；地址格式分类本身不能证明可路由或可达。

路由中按 ASN 查询的 PeeringDB、CAIDA 和公告列表属于补充资料，不作为独立的目标 IP 起源证据。目标范围或查询 ASN 不匹配的响应保留明细但不计有效；真实目标 IP 的路由 ASN 分歧和多起源公告会进入总览与报告。

### 只让有效证据投票

每条来源记录都保留 `pending`、成功、部分、超时、错误等状态。只有完成字段归一化且满足当前指标条件的记录才标记为 `voteEligible`：

```text
可投票来源 → 参与国家 / ASN / 组织等共识
超时或失败 → 保留失败证据，不投票
字段缺失   → 只用于已有字段，不构造虚假冲突
```

明细覆盖率表示“本轮有多少真实来源返回了可用于当前指标的字段”；总览采用下述固定模块权重，不会因 HTTP 失败而缩小分母。覆盖率不是页面加载进度或安全分数。

### 按来源结构归一化

不同 IP 服务对国家、地区、ASN、组织、代理类型的字段命名并不一致。项目为每个来源维护独立适配逻辑，再转换到统一记录结构；某个来源未返回的字段不会由其他字段猜测补齐。

IPv6 先规范化再比较；组织名称统一大小写、空白、标点与连接符后投票，不强行合并不同公司名称。共识至少需要 3 票，领先项占比至少 60%，且领先第二名至少 2 票；少票、平票或弱多数保持待核对。

### 网络参考分与覆盖率

- 总览覆盖率权重：HTTP 出口 10%、IP 情报 25%、路由注册 20%、完整 STUN 收集 20%、DNS 15%、AI 探针 10%。不透明 AI 响应仅计半份观察证据，不计可用服务。
- 网络参考分与来源覆盖率分别计算。评分维度权重为：IP 归属 20、路由 15、WebRTC 25、DNS 地区 10、来源风险标签 10、时区 5、语言地区 5、AI 服务路径 10。按实际可核对权重归一化：`已核对且无分歧的权重 ÷ 已核对权重 × 100`，四舍五入。每个维度中的双栈或探针平分权重；缺失权重不参与分子、分母，不当作通过或扣分。
- DNS 地区统一与双栈已知出口比较；缺少解析器地区或出口共识时保持“证据不足”。请求失败、回显路径不同和真实字段分歧分别展示，不混计为“明确冲突”；票数不足不标成“地区分歧”。
- 至少一个 HTTP 出口有可靠国家共识和 3 个可用情报来源，且可核对权重达到 40/100，才生成参考分；不足时显示“—”和具体未评分原因。缺少某地址族 WebRTC、DNS 或其他维度不会阻断已有证据评分，但会明确标记“部分证据”、列出未核对项及逐维度构成，不显示“状态稳定”。即使收集不完整，已经观察到的冲突也不会被丢弃。
- 组织名称差异只作标签说明，不计为国家 / ASN 的明确冲突或据此扣分；不会把不同公司名称强行认作同一家。摘要、明细和复制报告共用判断结果。
- 风险标签按 Proxy、VPN、Tor、Hosting 四项分别核对；某一项为否不能代替其他未知项。时区和语言逐地址族比较；AI 明确返回的 HTTP 受限与无法读取响应分别展示。
- DNS 有记录但部分出口或解析器地区未知时，只计入可核对的比例，不把整项作废；与任一已知出口地区相同的解析器不因双栈地区不同而误报冲突。
- 分数是可解释的诊断性规则，不是校准过的安全概率。高分也不能证明未核对项安全；不同未核对范围的分数不宜直接比较。未生成分数时圆环保持空白，避免把来源覆盖率误当评分。

网络参考分基于本轮可观察信号生成，不代表平台账号状态、封号概率或平台内部风控结论。

## 检测语义

### 服务连通不是账号状态

新版保留“路径已读取”“资源可达”“响应不可核对”“HTTP 受限 / 异常”“超时”“无法读取”等状态。`no-cors` 返回的不透明响应无法读取 HTTP 状态和正文，只能记为待核对，不能宣称服务正常。

“资源可达”不代表已登录、账号可用、地区解锁、支付成功或完整业务正常；探针失败也不等于平台宕机。扩展拦截、DNS / TLS 失败、跨域策略、网络策略和超时都可能影响结果。当前 v2 不读取官方故障公告，也不检测完整对话业务。

### AI 路径不是物理位置

ChatGPT、Claude 的公开端点在允许读取时返回的国家和节点信息描述的是目标站看到的网络路径，不等于用户、运营商或服务器的真实物理位置。Gemini 的资源探针没有出口回显，不会伪造该字段。分流、WARP、Private Relay 和按域名代理可能让不同目标看到不同出口，页面保留差异而不强行合并。

### 指纹摘要不是用户身份

Canvas、WebAudio 和环境摘要用于观察当前浏览器的可见信号。相同摘要不代表同一用户，不同摘要也不必然代表不同设备。WebAudio 自测使用 `OfflineAudioContext` 连续离线渲染 3 轮，不连接实时音频设备，不申请麦克风权限。

## 隐私与数据边界

AI Signal Guard 是静态前端应用，没有自建诊断数据后端，但部分检测必须连接第三方公开服务。

| 数据或操作 | 是否产生外部请求 | 说明 |
|---|---:|---|
| 语言、时区、字体 API 能力、本地指纹摘要 | 否 | 在当前浏览器读取或计算 |
| WebAudio 三轮自测 | 否 | 仅使用离线音频计算图 |
| 出口 IP 与多源情报 | 是 | 第三方接口会看到请求网络元数据 |
| DNS 检测 | 是 | 依赖第三方 DNS 泄漏检测服务 |
| WebRTC / STUN | 是 | 连接 STUN 服务取得候选地址 |
| AI 服务路径与资源 | 是 | 请求对应公开端点或备用端点；不附带登录凭据 |
| 分享摘要 | 否 | 仅写入剪贴板；地址是否脱敏取决于隐私开关 |
| 复制给 AI 诊断 | 否 | 只写入剪贴板，不会自动发送给任何 AI |

第三方服务有各自的日志、隐私政策和可用性边界。对极高敏感环境，应在隔离浏览器或受控网络中评估是否运行外部检测。

## 报告脱敏策略

隐私开关同时控制页面、分享摘要与“复制给 AI 诊断”中的地址显示。默认显示地址原值，分享前可开启“隐私遮罩”：

- IPv4 保留前两段，后两段显示为 `x.x`。
- IPv6 只保留有限前缀组，不复制完整地址。
- DNS、WebRTC、路由范围与 AI 路径中的地址，包括说明文字内嵌的地址，统一脱敏。
- WebAudio 单轮摘要的显示与单独复制遵循隐私开关；总览报告不包含 WebAudio 或 Canvas 摘要原值。
- 遮罩是展示 / 复制层保护，不会改变浏览器向第三方发出的诊断请求，也不会从页面内存中删除原始证据。

用户需要自行选择粘贴目标；页面不会自动打开 AI、发送报告或创建外部会话。

## 适用场景

- 验证 VPN、代理、WARP 或分流规则是否按预期生效。
- 排查 DNS 和 WebRTC 是否暴露不同于 HTTP 出口的地址。
- 对比 IPv4 / IPv6、ASN、组织、地区、语言和时区是否一致。
- 理解浏览器可见的 Canvas、WebAudio、字体和设备摘要。
- 区分目标站路径差异、资源响应与无法核对的浏览器探针。
- 按需生成脱敏、可人工复核的网络诊断报告。

## 不适用场景

- 不能替代 VPN、匿名网络、反指纹浏览器或终端防护产品。
- 不能预测封号、保证解锁、证明账号安全或绕过平台风控。
- 不能把启发式网络类型、地理或身份画像当作法律、合规或身份认证结论。
- 不能在纯浏览器中完成需要系统权限、运营商内部数据或平台账户权限的验证。

## 快速使用

1. 打开 [https://betaer.github.io/AiSignalGuard/](https://betaer.github.io/AiSignalGuard/)。
2. 首次访问时选择给项目 Star（新窗口打开仓库），或点击“先测试”继续；只有明确选择后才开始检测，并记住 12 小时。根页与 `/v2/` 共享这次确认；只关闭弹窗或未确认就刷新不会自动授权。旧版本保存的展示时间戳不视为新版检测许可。
3. 等待 IP、DNS、WebRTC、路由、AI 服务路径和浏览器环境证据分阶段完成。

单独音频重测只在本地离线计算，不发起新的网络请求。若随后启动全局重测，会等待正在运行的音频任务完成；全局检测中不能再叠加新的音频任务。
4. 先看网络参考分、覆盖率和异常提示，再展开来源级证据核对。
5. 分享前按需开启隐私遮罩，再复制文本报告并自行粘贴到可信目标。

## 能力边界与许可

- 网络参考分和风险标签均为诊断性、启发式参考，不是平台账号状态、封号概率或平台内部风控结论。
- 第三方接口可能变更、限速、返回冲突或暂时不可用；页面会尽量保留失败证据，但无法保证外部来源持续可用。
- 仓库当前未附带开源许可证；浏览和审计代码不等于获得复制、修改或再分发授权。
