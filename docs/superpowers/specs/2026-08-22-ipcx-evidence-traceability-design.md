# IP.cx Demo 检测证据可追溯设计说明

## 目标

让 `index-ipcx.html` 中的检测结论可以逐项核对。任何由两个以上指标、来源、候选地址或检测节点共同得出的结论，展开后必须展示全部明细；「检测结果、证据说明、建议」只负责解释结论，不能替代明细列表。

## 全局规则

- 单项读取可以只展示结论说明；复合检测必须追加完整的「检测明细」列表。
- 摘要出现 `N 个`、`N 票`、`N / M`、多个指标名称或「多源、交叉、共识」时，明细数量和内容必须可核对。
- 成功、失败、超时、不可用和字段缺失都属于检测结果，必须列出，不能只展示成功项。
- 明细直接出现在当前详情行内，不增加第三层折叠、弹窗或独立证据页面。
- 同一批数据在多个位置出现时共用同一数据源，不复制维护两份静态内容。
- 页面继续使用本地模拟数据，并在明细标题附近说明「本地演示数据」。
- 一级组中的「N 项详情」是界面内容数量，不属于检测指标，不需要额外证据列表。

## 数据结构

页面脚本新增统一的证据目录 `evidenceCatalog`。基础数据集只定义一次，复合数据集通过组合基础数据得到：

- `dnsResolvers`：10 个 DNS 解析器，包含解析器地址、服务商、国家 / 城市、状态和响应时间。
- `stunNodes`：8 个 STUN 节点，包含节点地址、公网候选、状态和响应时间；必须保留 6 个响应与 2 个超时。
- `ipIntelSources`：4 个 IP 情报来源，固定为 ipwho.is、ip.sb、country.is、db-ip。
- `routeSources`：2 个路由与注册来源，固定为 ARIN、ASN Lookup。
- `unavailableSources`：2 个未成功参与本轮判断的来源，固定为 IPinfo（浏览器请求超时）与 AbuseIPDB（演示环境未配置令牌），保留失败原因。
- `geoVotes`：复用 4 个 IP 情报来源与 2 个路由来源，共 6 票。
- `sourceCoverage`：复用 6 个可用来源并加入 2 个不可用来源，共 8 项。
- 浏览器、网络类型、风险标签和一致性检查使用独立的小型指标集，每个指标包含名称、观测值、补充信息、状态与状态色。

每个证据项使用同一字段模型：

```js
{
  name: "指标或来源名称",
  value: "本轮观测值",
  meta: "地址、地区、归属或检测方式",
  status: "一致 / 可用 / 超时 / 待核对",
  tone: "good / warn / bad / neutral"
}
```

详情 HTML 只保留声明式占位节点：

```html
<section class="metric-evidence" data-evidence-set="dnsResolvers" data-evidence-title="解析器明细"></section>
```

初始化时由 `renderEvidenceLists()` 读取数据集并生成可访问的有序列表。一个数据集可以渲染到多个占位节点，例如 DNS 泄漏与 DNS 地区一致性共用 `dnsResolvers`。

## 明细列表视觉与交互

- 明细区位于三张说明卡下方，标题格式为「检测明细 · N 项」，右侧显示「本地演示数据」。
- 桌面端每项按「序号 / 指标或来源 / 观测值 / 状态」排列；补充信息显示在名称下方。
- 手机端保持一个证据项一行，名称与状态在第一行，补充信息与观测值在第二行；长地址允许换行，不允许横向滚动。
- 状态沿用现有绿色、琥珀色和红色语义，不增加 Emoji。
- 列表项之间使用低对比度细线；列表外框与现有详情卡保持一致，不制造新的大标题卡。
- 展开详情行后立即看到明细列表，不需要再次点击。

## 现有独立视图同步

- WebRTC 独立视图的 STUN 列表必须从当前 4 条补齐为 8 条，并与 `stunNodes` 使用同一数据。
- 浏览器指纹独立视图已经列出平台、屏幕、字体度量、Canvas / WebGL 四项证据，保留现有结构。
- 分享图仍只展示摘要，不加入长明细列表。

## 一致性与校验

- `10 个解析器一致`必须对应 10 条 `dnsResolvers`。
- `US · 6 票`必须对应 6 条 `geoVotes`，且每条都显示本轮国家判断。
- `6 / 8 来源可用`必须对应 8 条 `sourceCoverage`，其中 6 条可用、2 条不可用。
- `4 / 4`与`2 / 2`必须分别对应 4 条 `ipIntelSources`和 2 条 `routeSources`。
- `6 / 8 响应`必须对应 8 条 `stunNodes`，其中 6 条成功、2 条超时。
- 相同数据集在不同位置渲染出的条目数量、状态和值必须一致。

## 验收标准

- 18 条复合详情展开后均出现完整检测明细，系统时区保持单项说明。
- 所有摘要数量、票数和分母均能逐条核对，没有「等」或省略项代替列表。
- DNS 的两个详情行都展示同一组 10 个解析器；地理判断与主流地区都展示同一组 6 个来源。
- 网络标签共识明确显示 6 个可用来源与 2 个不可用来源。
- WebRTC 总览详情和独立视图都展示同一组 8 个 STUN 节点。
- 390px 与 320px 宽度下无横向滚动，长 IP、域名和来源名称可读。
- 隐私遮罩、一级折叠、详情折叠、分享图、复制摘要和模块切换不受影响。
- 内联 JavaScript 语法、生产构建和现有自动化测试全部通过。
