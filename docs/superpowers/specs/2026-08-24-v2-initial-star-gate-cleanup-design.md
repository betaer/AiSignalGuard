# AI Signal Guard v2 首轮 Star 闸门与页面清理设计

## 目标

最新版根入口与 `/v2/` 在首次访问时先展示现有 Star 支持弹窗，用户明确点击 Star 或“先测试”后才开始本轮完整检测。弹窗展示后进入 12 小时静默期，期间刷新或点击右下角重新检测都不再弹窗。同时清除最新版页脚的自返入口和相关无用样式，并把 JA3 / JA4 统一为第 5 条检测边界说明。

## 版本边界

- 同步修改根 `index.html` 与 `v2/index.html`，保持两个最新版入口除相对资源路径外完全一致。
- 保留 `/v1/` 在线归档及其 `app.min.js`、`styles.min.css` 等依赖，不修改 `v1/index.html`。
- 不删除或修改 IPCX、IPCX Remix、Demo、日期归档页面和历史 Git Tag / Release。
- “旧 UI 清理”只指最新版中已经失去用途的自返链接、链接专属样式与独立 JA3 / JA4 大卡片结构。

## 统一检测闸门

最新版建立一个统一的检测请求入口，负责首次检测与右下角重新检测：

1. 页面完成静态 DOM、事件和视图初始化后，首次检测先查询 `AISGStarPromptPolicy`。
2. 若 12 小时静默期仍有效，立即启动完整首次检测，不展示弹窗。
3. 若需要提示且原生 `dialog.showModal()` 可用，记录待执行检测类型、写入 12 小时截止时间并显示弹窗；弹窗显示前不启动网络、DNS、WebRTC、WebAudio 或浏览器指纹计算。
4. 若浏览器不支持原生对话框，安全降级为直接开始检测，不阻断产品能力。
5. 结果页点击右下角重新检测时复用同一频控判断；静默期内直接进入现有全屏重新检测 Loading。

待执行状态不再使用只表达重测的 `pendingRecheck` 布尔值，而是区分 `initial` 与 `recheck`。这样弹窗按钮可以准确恢复对应流程，避免首次检测误走重测 Loading 或重测误走首轮静默检测。

## 弹窗交互与频控

- 弹窗保留截图中的深色视觉、🤩 图标、关闭按钮、GitHub 主操作和“先测试”次操作。
- 点击“行，给你一颗 Star”：浏览器按真实链接行为在新窗口打开 `https://github.com/betaer/AiSignalGuard`；当前页同时关闭弹窗并执行待处理检测。
- 点击“先测试，用好了再回来”：关闭弹窗并执行待处理检测，不打开外部页面。
- 点击右上角关闭：关闭弹窗并取消当前待处理检测，不在后台继续运行。
- ESC 与点击遮罩不关闭弹窗，维持已有明确选择约束。
- 12 小时频控从弹窗实际展示时开始，使用已有 Cookie 与 LocalStorage 双写策略。无论用户点击 Star、先测试或关闭，12 小时内刷新页面与右下角重测都不再展示弹窗。
- 用户关闭后若在 12 小时内刷新，页面因静默期有效而直接开始完整检测。

## 完整检测范围

“点击后才开始检测”覆盖最新版所有主动计算与外部探测：

- WebAudio 三轮离线渲染；
- 本地稳定摘要与宽域摘要计算；
- IP、DNS、WebRTC、IP 情报、路由注册等实时检测；
- 页面检测结果渲染与相关完成播报。

弹窗出现前只允许静态页面初始化、事件绑定、折叠状态和导航状态计算，不产生上述检测请求或指纹计算结果。

## 页脚与旧结构清理

- 根页删除指向 `./` 的“返回正式首页 →”。
- `/v2/` 删除指向 `../` 的“返回正式首页 →”。
- 页脚继续保留“实时结果不写入服务器 · 第三方来源可能看到本轮目标 IP”。
- 页脚由两端布局收敛为单一说明文本布局，删除 `.site-footer a` 和移动端仅服务于该链接的样式。
- 不删除通用 `.site-footer`，因为隐私说明和页面底部留白仍依赖它。

## JA3 / JA4 边界说明

- “检测边界与建议”计数从 `4 项` 改为 `5 项`。
- 删除独立的 `fingerprint-tls-card` 大卡片及仅服务于它的外边距样式。
- 在现有 `fingerprint-boundary-list` 末尾加入统一的第 5 条：

> **JA3 / JA4 不可直接读取**
>
> 普通网页脚本无法访问 TLS ClientHello，因此本页不会生成或伪造 JA3 / JA4 值。

- 保留内部 `tls` 指纹状态及 AI 报告中的 JA3 / JA4 能力边界，避免页面展示与复制报告矛盾；本次只调整可见信息结构，不伪造协议指纹。

## 测试与发布

- 版本契约验证根页与 v2 同步、页脚不再包含自返入口、边界计数为 5、JA3 / JA4 采用列表项且不存在独立 TLS 卡片。
- Star 流程契约验证首次检测和重测共用统一闸门，待执行状态能区分 `initial` / `recheck`，12 小时策略继续由现有模块负责。
- Playwright 验证无静默记录时首屏弹窗可见且检测请求数为 0；Star 与“先测试”分别启动完整检测；关闭按钮取消本轮检测；12 小时内刷新和重新检测均不再弹窗。
- 验证桌面、390px、300px 弹窗和页脚无溢出，根页与 `/v2/` 无运行时错误。
- 执行 `npm run check:full`，推送 `main` 后等待 GitHub Pages 构建成功，并在线核验根入口、`/v2/` 和保留的 `/v1/`。
