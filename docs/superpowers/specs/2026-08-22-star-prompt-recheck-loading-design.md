# Star 提示频控与重测揭晓流程设计

## 目标

统一正式页首次检测、自动倒计时检测、正式页重新检测和 `index-ipcx.html` 重新检测的 Star 提示策略；同时优化 IPCX 摘要文案、状态措辞与重测 Loading 仪式感。

## 文案定稿

- 摘要标题改为“AI Signal Guard · 通用数字环境检测”。
- 标题下一行加入 `https://betaer.github.io/AiSignalGuard/`。
- “时区待核对”改为“时区不一致”，“语言待核对”改为“语言不一致”。两项信号都能正常读取，问题是它们与当前美国出口环境不一致，因此不使用容易误解为功能故障的“异常”。
- AI 诊断复制成功提示改为“已复制，请发给AI协助排查解决问题 👨‍🔧”。
- IPCX 结果卡、关键状态和证据明细使用同一套“不一致”措辞，避免页面与复制内容矛盾。

## 12 小时 Star 提示规则

- 使用名为 `aisg-star-prompt-until` 的站点 Cookie 保存截止时间，生命周期 12 小时，配置 `Path=/` 与 `SameSite=Lax`；HTTPS 环境追加 `Secure`。
- 为兼容 `file://` 本地预览无法可靠写 Cookie 的情况，同步写入同名 `localStorage`；读取时使用两者中有效的较晚截止时间。
- 频控从弹窗实际展示时开始计算，因此用户通过 Star、继续按钮或关闭按钮处理弹窗后，12 小时内都不会重复看到。
- 每次发起检测时重新判断截止时间；到期后的下一次检测或重测再次展示弹窗。
- 点击 Star：保留 GitHub 新窗口导航，同时关闭弹窗并执行待处理检测。
- 点击“先测试”：关闭弹窗并执行待处理检测。
- 点击 X：关闭弹窗并取消本次待处理检测。
- 禁止 ESC 和点击黑色遮罩区关闭，延续既有交互约束。

## 检测与 Loading 流程

- 正式页首次分析和倒计时分析沿用现有三阶段页面结构；通过频控后进入现有分析进度页。
- 正式页结果页点击“重新检测”时也切换回现有分析进度页，不再停留在旧结果上静默刷新。
- IPCX Demo 增加全屏 Loading 揭晓层，依次显示“读取浏览器与时区信号”“交叉核对 DNS、WebRTC 与多源数据”“生成检测结论”，结束后更新检测时间、恢复结果并播报完成。
- Loading 期间禁用浮动重测按钮，防止并发流程；兼容 `prefers-reduced-motion`。

## 测试与验收

- Node 测试覆盖截止时间解析、有效期边界、Cookie / 本地存储降级和摘要文案契约。
- 静态契约确保正式页 Star 主按钮绑定继续检测、结果重测进入 Running 阶段，IPCX 存在弹窗和 Loading。
- 浏览器验证第一次重测弹窗、Star 后继续、12 小时内再次重测直接 Loading、Loading 完成后揭晓结果、移动端无溢出。
- 完整运行 `npm test`、脚本语法检查和 `git diff --check`。
