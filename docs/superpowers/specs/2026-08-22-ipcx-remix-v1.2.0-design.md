# IPCX Remix v1.2.0 设计说明

## 目标

以当前 `index-ipcx.html`、`ipcxApp.js` 与 `ipcxEvidence.js` 的最新实时检测实现为基线，创建一个完全独立、可部署、可测试的混合信息架构原型：

- 新页面文件固定为 `index-ipcx-remix-v1.2.0.html`，页面标题和可见版本标识均包含 `v1.2.0`。
- 新控制器固定为 `ipcx-remix-v1.2.0.js`，从当前 `ipcxApp.js` 复制后独立演进。
- 继续复用 `ipcxEvidence.js` 的实时证据采集与归一化能力。
- 保留原始 `index-ipcx.html`、`ipcxApp.js` 和 `ipcxEvidence.js` 的行为，不把 Remix 试验性结构反向写回正式 IPCX 页面。
- 将“先给结论、再看证据”的结果中心，与按需进入的高级工具中心组合到同一个纯静态 SPA 中。

Remix 是真实证据驱动的结构原型，不是静态假数据展示页；尚未接入的高级工具必须明确显示“未启用”或“规划中”，不得伪造成功结果、节点数量、延迟或风险结论。

## 非目标

- 本版不实现 1,648 节点 Multi、40 目标分流、24 项 CDN、完整多生态 DNS 或 22 节点 STUN 的真实联网逻辑。
- 本版不增加服务器、数据库、API Key 或持久化用户记录。
- 本版不修改生产首页 `index.html`，也不把 Remix 设置为默认入口。
- 本版不修改 `package.json` 的项目版本号；`v1.2.0` 只标识 Remix 页面版本。
- 本版不声称普通浏览器已经能够读取 JA3 / JA4、完整 TLS ClientHello 或商业信誉库。

- `ipcx-remix-v1.2.0.js`：从最新 `ipcxApp.js` 复制并适配的独立控制器；负责实时证据渲染、Hash 路由、隐私遮罩、折叠状态、复制、重测和焦点管理。

## 信息架构

### 结果中心

结果中心使用五个稳定路由。桌面显示完整名称，窄屏显示短名称：

| Hash 路由 | 桌面名称 | 手机名称 | 内容 |
| --- | --- | --- | --- |
| `#/overview` | 总览 | 总览 | 综合结论、覆盖率、优先问题、当前画像、核心事实 |
| `#/network` | 网络身份 | 出口 | IPv4 / IPv6、地理、ASN / 组织、网络类型、多源互证 |
| `#/leaks` | 泄漏与解析 | 泄漏 | DNS、WebRTC、STUN 的实时结论、失败语义与证据 |
| `#/paths` | 路径与节点 | 路径 | 当前可用的路径摘要；分流、CDN、服务路径等未接入项显示中性边界卡 |
| `#/browser` | 浏览器环境 | 设备 | 语言、时区、Emoji、字体、Canvas、音频、WebGL 与不可直接读取的 TLS 边界 |

一级导航使用普通 Hash 链接，而不是不完整的 ARIA Tab。当前项使用 `aria-current="page"`，刷新、前进、后退和直接打开 Hash 均恢复同一视图。路由切换后把焦点移动到当前视图标题，并通过礼貌型状态区播报。

总览展示完整结论卡；其他路由只保留一个紧凑状态条，避免重复占用首屏。

### 高级工具中心

`#/tools` 展示七个工具卡，工具详情使用独立 Hash：

- `#/tools/ip`
- `#/tools/dns`
- `#/tools/stun`
- `#/tools/cdn`
- `#/tools/split`
- `#/tools/multi`
- `#/tools/latency`

每张工具卡必须展示：用途、预计探针规模、网络成本、隐私等级、是否需要主动确认、当前实现状态。未接入工具的主按钮为“查看检测边界”，不能显示“开始检测”或虚构的运行结果。

工具详情与结果域使用不同样式前缀；不得复用 `.signal-row`、现有 `data-row-id` 或当前证据容器类，避免破坏实时控制器对 19 条核心详情的完整性校验。

## 实时证据兼容

- 保留当前 19 个唯一 `data-row-id`，名称和值只由实时状态生成。
- 保留 `ipcxEvidence.js` 所需的所有 DOM `id`、数据属性，并固定按 `starPromptPolicy.js` → `ipcxEvidence.js` → `ipcx-remix-v1.2.0.js` 的顺序加载脚本。
- 初始 HTML 中的 IP、ASN、组织、城市、屏幕尺寸、平台、指纹和风险结论全部使用中性“读取中 / 未确认”占位。
- 网络失败、CORS、WebRTC 不可用、STUN 超时和来源字段缺失统一保持“未知 / 未确认”，不能变成绿色安全结论。
- 路径与节点中的未接入能力不参与分数、覆盖率或风险判断。
- 不把高级工具卡计入现有 19 条详情数量，也不把规划数量伪装成已经完成的探针数量。

## 视觉与响应式设计

- 延续当前暖白、薄荷绿、深墨色和数据化排版，不引入新的紫蓝 AI 渐变或第三方字体依赖。
- 顶栏下方放置吸顶五域导航；320px 到 390px 视口必须完整可用，可使用短标签，但不能隐藏滚动条后制造不可发现的横向入口。
- 桌面结果区域使用“主报告 + 右侧上下文栏”的非对称网格；平板与手机自动收敛为单列。
- 一级证据组只自动展开 `warn`、`bad` 或 `unknown` 状态；明确正常的组默认收起。
- 浏览器信号来源以卡片或证据列表展示，不再使用 Tab 套 Tab。
- 手机底部只固定“重测、隐私、分享”三项；更多操作进入菜单。页面底部必须包含安全区和工具栏补偿，不得覆盖内容或焦点元素。
- 动画只用于路由切换、状态变化和进度反馈，并遵守 `prefers-reduced-motion`。

## 隐私与文案

- 清楚区分“结果不上传到自有服务器”和“浏览器会直接请求第三方检测服务”。
- 隐私遮罩覆盖 IPv4、IPv6、mDNS、指纹、精确城市、ASN / 组织与复制报告中的敏感字段。
- 页面不内置 API Key、真实用户地址或固定可识别设备数据。
- 高隐私工具必须展示主动确认要求；本版未实现真实运行，因此不会触发确认或外部探针。
- Star 支持入口改为非阻断式页脚或更多菜单项，不在用户获得结果前弹出模态框。

## 无障碍

- 保留跳过链接、语义标题层级、原生 `<details>`、可见焦点和 `aria-live`。
- Hash 导航使用 `<a>`，支持 Tab / Shift+Tab / Enter 和浏览器原生历史行为。
- 所有可点击目标在手机端至少 44 × 44 CSS 像素。
- 小字号正文和状态文字满足 4.5:1 对比度目标；非文字控件满足 3:1。
- 工具详情有明确返回工具中心的链接，不产生键盘死路。
- 隐私、重测和分享状态变化必须有文本反馈，不能只依赖颜色或动画。

## 测试策略

### TDD 合同测试

实现前先创建失败测试，覆盖：

- 版本化文件名、页面标题和可见版本号。
- 五个结果路由、七个工具路由和唯一 Hash。
- 19 个核心 `data-row-id` 仍然唯一且完整。
- 初始 HTML 不包含固定 IP、城市、ASN、平台、屏幕、JA3 / JA4 或成功结论。
- 未接入工具全部显示中性状态且不计分。
- 导航、标题、焦点目标、状态区和三项移动操作结构完整。
- Remix HTML / JS 已加入构建清单与 npm 测试脚本。

### 真实浏览器测试

Remix E2E 使用本地 HTTP Server、Chromium、`serviceWorkers: "block"`，并拦截全部非 localhost HTTP、WebSocket 与 WebRTC 外部行为。覆盖：

1. 无 Hash 和非法 Hash 回退 `#/overview`。
2. 五个结果路由点击、刷新、前进、后退与直接深链。
3. 工具中心和七个工具详情的进入、返回与中性状态。
4. Tab / Shift+Tab / Enter 键盘路径、焦点移动和 `aria-current`。
5. 隐私遮罩在各结果域与复制摘要中保持一致。
6. 320×700、390×844、844×390 横屏、768×900、1200×800、1440×1000 六个视口无页面横向溢出。
7. 吸顶导航、底部操作栏和安全区不覆盖标题、详情、焦点目标或页面末尾。
8. 实时证据全部失败时仍显示未确认，不出现虚假绿色结论。
9. 外部 HTTP、WebSocket 和 WebRTC 均未真正发出。

浏览器测试同时启用 Chromium JavaScript Coverage，只统计 `ipcx-remix-v1.2.0.js`，完成五个结果域、工具中心、七个工具详情、隐私、重测、复制、返回和错误 Hash 流程后，已执行字节覆盖率必须达到 80% 以上。路由规范化、工具目录和状态判断的每个分支还必须由确定性合同或单元断言覆盖，避免只靠页面加载抬高覆盖率。

### 构建与 Worker

- `npm run build` 后 `dist/index-ipcx-remix-v1.2.0.html` 与 `dist/ipcx-remix-v1.2.0.js` 存在。
- Worker 对两个文件的 GET 返回 200，HEAD 返回 200 且无响应体。
- Worker 返回正确的 HTML / JavaScript 内容类型与既有安全响应头；不存在的 `index-ipcx-remix-v1.2.1.html` 必须返回 404，不能回退或误命中旧版本。
- 原始 `index-ipcx.html` 和 `ipcxApp.js` 的现有合同与 E2E 全部继续通过。

### 多轮验证

实现完成后执行以下轮次：

1. Remix 合同测试连续运行 3 次。
2. Remix E2E 连续运行 3 次。
3. `npm test` 完整运行 1 次。
4. `npm run test:e2e` 完整运行 1 次。
5. `npm run check:full` 最终运行 1 次。
6. 使用真实有头 Chromium 在 1440px 桌面和 390px 手机各完成一轮截图与交互验收。

任何一轮失败都必须定位原因、修复后从该轮重新开始；不得把偶发失败当作通过。

## 验收标准

- 新页面准确命名为 `index-ipcx-remix-v1.2.0.html`，原始 IPCX 三个核心文件保持不变。
- 五个结果域和高级工具中心具备完整、可分享、可回退的 Hash 路由。
- 页面继续显示真实 IPCX 证据；未接入能力没有伪造数据或成功状态。
- 手机端没有横向溢出、导航不可发现、工具栏遮挡或小于 44px 的核心交互目标。
- 键盘可以访问所有一级入口、工具入口和操作按钮，焦点与状态播报正确。
- 静态构建和 Worker 能正确提供版本化 HTML / JS。
- Remix 定向测试多轮稳定通过，现有 IPCX、正式页、构建和 Worker 回归全部通过。
